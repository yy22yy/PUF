TENAX: Tensor-Train Driven PUF Modeling
Under Strict Query Constraints

Anonymous NDSS Submission

Abstract—Physical Unclonable Functions (PUFs) serve as
foundational hardware roots of trust for chip authentication,
cryptographic key generation, and supply chain protection. To
defend these critical authentication primitives against rogue
characterization in wild IoT deployments, practical silicon
architectures enforce strict query limits. However, such severe
query constraints simultaneously restrict the sample budgets
available for proactive defensive security auditing, while ex-
isting hardware evaluation methods universally suffer from
exponential parameter explosion, heavy reliance on massive
challenge-response pairs (CRPs), and prolonged profiling la-
tency. To bridge this operational gap and enable practical,
pre-deployment security verification, we present TENAX, an
automated, grey-box penetration testing and security auditing
framework specifically engineered for PUF-based hardware
roots of trust. Driven by an innovative Tensor-Train core opti-
mized over an expanded feature domain, TENAX confines the
multi-chain auditing complexity to a polynomial scale without
sacrificing physical representation power, thereby drastically
maximizing data utilization and convergence stability under
strict query starvation. Extensive red-team penetration exper-
iments on both simulated benchmarks and commercial FPGA
silicon validate TENAX’s efficacy as a sample-efficient auditing
tool. On the challenging 128-bit 7-XOR APUF, TENAX achieves
97.29% modeling accuracy with only 20M CRPs in 6.61 hours,
whereas conventional modeling baselines require 400M CRPs
and 196.77 hours to reach comparable accuracy, yielding a
20× reduction in query budget and a 29.8× auditing speedup.
On the 64-bit 8-XOR APUF, TENAX reduces the parameter
space from 364,700 (in uncompressed tensor representations)
down to 1,042, achieving a reduction of over two orders of
magnitude. We further validate its robustness against physical
environmental fluctuations through hardware implementations
on 28 nm and 45 nm FPGAs across cross-technology discrepan-
cies. By supporting XOR APUFs, iPUFs, and LSPUFs within
a unified mathematical engine, TENAX establishes a highly
versatile, sample-efficient, and automated pentesting utility for
rigorously quantifying the security margins of contemporary
hardware roots of trust.

As hardware security becomes an increasingly critical cor-
nerstone of modern computing systems, physical unclonable
functions (PUFs) have emerged as vital hardware roots
of trust. By leveraging manufacturing variations to pro-
duce device-specific challenge-response pairs (CRPs), PUFs
provide a foundational substrate for secure chip authenti-
cation, cryptographic key derivation, and supply chain pro-

To safeguard these hardware roots of trust against rogue
characterization, practical silicon architectures enforce strict

vulnerability profiles. Although advanced high-dimensional
regression and structural learning models attempt to mitigate
the curse of dimensionality, they universally suffer from
severe parameter inflation [18], [22], [23], limiting their
scalability for rapid, sample-efficient automated auditing.

In real-world IoT deployments, PUF-based authentication
operates across two distinct phases: Enrollment (where the
server challenges the device and constructs an initial refer-
ence profile) and Authentication (where incoming responses
are verified against stored models). Crucially, this opera-
tional flow dictates two practical security implications often
overlooked in existing literature. First, due to environmental
noise and hardware non-idealities, protocol verification tol-
erates a non-zero bit error rate. Hence, an attacker does not
require 100% modeling accuracy to successfully spoof au-
thentication. Second, while defense designs implement strict
query budgets during authentication to limit CRP harvesting,
this budget cannot be reduced infinitely without triggering
severe False Rejection Rates (FRR) and Denial-of-Service
(DoS) on legitimate, noise-affected devices. Consequently,
evaluating PUF security under stringent yet operational
query limits represents a vital prerequisite for IoT security
design.

To overcome these scalability deadlocks, one might nat-
urally expect that deploying modern automated pentesting
tools, such as agentic Large Language Models (LLMs) or
Reinforcement Learning (RL)-tuned pentesting agents, could
streamline the verification workflow. In practice, however,
such high-level agentic automation fails to resolve the
core technical bottleneck when the underlying hardware
assessment engine itself remains heavily over-parameterized.

Confronted with an excessively large parameter search space
under strict query constraints, prompt-based or RL-driven
security agents inevitably suffer from inefficient trial-and-
error, sparse optimization feedback, and prohibitive eval-
uation latency. Consequently, without first fundamentally
collapsing the structural complexity of the core mathematical
evaluation model, high-level automated assistance alone can-
not deliver reliable or scalable gains in pentesting efficiency,
data utilization, or final characterization fidelity.

Despite recent progress, three critical bottlenecks in hard-
ware pentesting and automated security auditing remain
insufficiently addressed:

• Issue 1: Parameter hyper-inflation. Contemporary
pentesting methods evaluate security by constructing
surrogate models of target PUFs. However, these high-
dimensional models suffer from excessive parameter
complexity. As the compositional scale of the hardware
target increases, structural representation requirements
expand sharply, resulting in heavily over-parameterized
frameworks that are prohibitive to optimize under data-
starved regimes. Consequently, they are prone to severe
overfitting and tend to overestimate the necessary query
budget for characterization.

• Issue 2: Audit efficiency vs. fidelity trade-off. Current
verification methods fail
to strike a viable balance
between sample efficiency and assessment accuracy.
In practice, they demand massive volumes of CRPs
and prolonged execution latency to achieve depend-
able characterization on complex primitives. Automated
assistance, such as agentic LLMs or reinforcement-
learning-based approaches, remains bottlenecked in this
setting. They inherently depend on expensive evaluation
loops and often require auxiliary side-channel signals
beyond raw, response-only supervision.

• Issue 3: Restricted Architectural Versatility. Mod-
ern strong PUFs resist modeling attack through either
enhanced structural non-linearity (e.g., XOR APUFs,
iPUFs) or input-output correlation obfuscation (e.g.,
LSPUFs). Existing pentesting tools are rarely versa-
tile enough to bridge both design paradigms. Their
characterization robustness drops significantly when
confronted with complex architectural variants and
physical environmental noise in deployed silicon.

To resolve these foundational bottlenecks, we pro-
pose TENAX (Tensor-train Enhanced Network Assessment
for XOR-based PUF architectures), an automated, query-
efficient hardware pentesting framework engineered for
compositional roots of trust under strict access restric-
tions. At its core, TENAX leverages a unified architecture
that directly executes tensor factorization within the PCA-
expanded feature domain. This intrinsic mathematical syn-
ergy collapses the parameter representation complexity of
multi-chain designs from an exponential to a polynomial
scale. Consequently, TENAX drastically maximizes data
efficiency under rigid query budgets, enabling generalized,
high-fidelity characterization across diverse compositional
architectures (e.g., XOR APUFs, iPUFs, and LSPUFs) as

well as non-ideal physical silicon without relying on out-of-
band validation channels.

Extensive red-team penetration experiments on both sim-
ulated benchmarks and commercial FPGA implementations
demonstrate that TENAX effectively shatters the data and
latency bottlenecks in hardware security auditing. On a 128-
bit 7-XOR APUF, TENAX consumes only 5% of the CRP
budget required by SOTA pentesting baselines while cutting
execution time from 196.77 hours to 6.61 hours, achieving a
29.77× speedup alongside a 97.29% characterization accu-
racy. These empirical findings prove that current hardware
rate-limiting thresholds severely overestimate actual physical
security margins; onboard access controls must enforce CRP
lockout budgets far more strictly than previously assumed.

III. Constrained Characterization Setup

To establish a realistic security baseline for embedded hard-
ware roots of trust, we formalize a query-constrained eval-
uation framework that reflects actual deployment conditions
in edge IoT systems.

A. Threat Model and Grey-Box Assumption

Unlike unconstrained machine learning (ML) setups, we
consider a non-invasive grey-box evaluation scenario. In
practical IoT ecosystems, an adversary or security auditor
can acquire off-the-shelf target devices via commercial chan-
nels and perform standard non-invasive reverse engineering
(e.g., board teardown or architectural inspection). Conse-
quently, high-level structural parameters, such as the number
of constituent APUF chains x and the challenge bit-width
n, are assumed to be publicly known. This assumption is
also consistent with the mainstream PUF modeling methods
compared in Section V.

However, fine-grained physical fingerprints, such as in-
dividual stage propagation delays and silicon-level manufac-
turing variation offsets, remain strictly unknown and unob-
servable. Furthermore, characterization must be conducted
non-invasively through standard physical interfaces without
layout modification, or
internal silicon probing, physical
thermal/voltage fault
injection. Such destructive physical
measures are excluded from our evaluation framework.
Destruction of PUF chips violates basic attack economics
in IoT scenarios. More importantly, because each silicon
instance possesses a unique, uncloneable hardware signature,

physically destroying or extracting data from one target chip
provides zero transferable utility for attacking other devices
in the same fleet.

Finally, we evaluate characterization performed over di-
rect, raw CRP interfaces. Heavy cryptographic masking
layers and public-key challenge obfuscation mechanisms
are deliberately excluded from our scope. Such advanced
countermeasures incur non-negligible area and energy over-
heads that are often unaffordable for strictly constrained
edge IoT nodes. Therefore, this work focuses on auditing
the intrinsic, unmasked physical security baseline of the
hardware primitive itself.

B. Query-Constrained Pentesting

To model practical security verification without triggering
device lockout, the characterization workflow operates under
four operational constraints:

• Query Starvation (Dauth ≪ Dbudget): On-device rate-
limiting and query control mechanisms restrict total
CRP acquisition to a strictly bounded budget Dbudget,
mimicking real-world authentication rate caps.

• Response-Only Supervision: Evaluators can only ob-
serve binary output pairs (Ci, Ri). No auxiliary side-
channel signals, analog timing traces, or multi-query
reliability statistics are accessible.

• Practical Success Threshold (ϵtol): Because practical
authentication protocols employ fuzzy matching to ac-
commodate environmental noise, successful character-
ization requires constructing an estimator ˆf achieving
accuracy Acc( ˆf ) ≥ 1 − ϵtol, rather than exact 100%
parameter cloning.

• Strict Zero-Oracle Auditing: To prevent evaluation
leakage, once the budget Dbudget
is collected, all
model synthesis, hyperparameter tuning, and conver-
gence checks must rely strictly on self-contained op-
timization within Dbudget, completely blind to external
validation oracles or post-hoc querying.

IV. Proposed Pentesting Framework

A. Architecture and Workflow

Fig. 3 illustrates the end-to-end workflow of TENAX from
a Red Team penetration testing perspective. Given an input
binary challenge, TENAX builds a unified PCA-expanded
feature domain. All subsequent tensor regression operations
are defined over this feature domain. The weight tensor
corresponding to expanded features is factorized into a set
of lightweight TT core tensors. Each core tensor undergoes
mode-2 contraction against the PCA-expanded input features
to yield intermediate matrices, and sequential matrix multi-
plication across all cores approximates the required tensor
inner product. Finally, the resulting value is combined with
a learnable bias and passed through a sigmoid activation,
allowing the Red Team to output the predicted PUF response
during penetration assessment.

The proposed framework structurally resolves the three
core technical bottlenecks outlined in Section I through three
tightly coupled design principles of TENAX:

(1) Tensor-Train Core Factorization (for Issue 1: Parameter
Hyper-Inflation): To eliminate parameter explosion in multi-
chain targets, TENAX factorizes the ultra-high-dimensional
weight tensor into a linear chain of low-rank third-order core
tensors. This structural factorization collapses the parameter
representation complexity from an exponential scale down
to a strict polynomial bound O(nx2a+1), fundamentally
suppressing overfitting risks and removing optimization bot-
tlenecks under data-starved regimes.
(2) Expanded Feature Synergy (for Issue 2: Efficiency vs.
Fidelity Boundary): To break the sample-efficiency deadlock
under severe query constraints, TENAX natively executes
all Tensor-Train core contractions within a PCA-expanded
parity feature domain. Rather than treating feature prepro-
cessing and tensor regression as decoupled operations, this
continuous feature-space integration drastically maximizes
information extraction per CRP, enabling ultra-low sample
consumption and accelerated convergence while retaining
near-optimal characterization fidelity.
(3) Unified Multi-Architecture Assessment (for Issue 3:
Restricted Versatility): To bridge heterogeneous hardware
defense paradigms, TENAX is engineered as a single,
architecture-agnostic evaluation engine. By unifying cross-
chain interaction modeling into a flexible tensor contraction
interface,
the framework seamlessly accommodates non-
linear compositions (XOR APUFs, iPUFs), obfuscated chal-
lenges (LSPUFs), and physical process variability in silicon
FPGAs without requiring design-specific architectural mod-
ifications.

3) The Evolution of Tensor Regression Frameworks in

inherently capture multilinear dependen-

ill-posed for orders greater than two, causing optimization
routines to fluctuate or collapse when data is scarce.

We now discuss the landscape of tensor-based vul-
nerability assessment. Tensor-based data analytics have
recently emerged as a highly promising paradigm for hard-
ware security evaluation. Unlike flattened machine learning
approaches that destroy structural alignment, tensor methods
intrinsically preserve the high-dimensional spatial and multi-
chain correlations inherent in compositional PUF architec-
tures.

Fundamentally, the technical spectrum of tensor analyt-
ics branches into two primary methodologies: CANDE-
COMP/PARAFAC (CP) decomposition and Tucker decom-
position. Due to its strict component uniqueness and high
interpretability under mild conditions, CP decomposition is
exceptionally suited for unsupervised pattern mining and
feature clustering. Consequently, prior hardware evaluation
frameworks, such as CP-based tensor modling [18], have
exclusively embraced the CP route.

Conversely, for generic Tucker decomposition, despite its
unparalleled data compression capacity, precise approxima-
tion control, and mathematical quasi-optimality (where re-
construction errors closely match the theoretical minimum),
it has been historically dismissed in hardware testing. As
formalised in Theorem 2, generic Tucker suffers from a
catastrophic curse of dimensionality because the parameter
volume of its monolithic core tensor scales exponentially
with the number of PUF chains. This limitation becomes
glaringly evident with concrete empirical values: when eval-
uating a standard 64-bit 8-XOR APUF with a target rank
Lmin = O(640.5) = 8, generic Tucker demands a colossal
core tensor requiring at least 88 ≈ 16.7 million learnable
variables, rendering it entirely unviable under tight query
constraints.

To break this methodological deadlock, TENAX intro-
duces a paradigm shift by pivoting to Tensor-Train (TT)
factorization, which is mathematically categorized as a spe-
cialized hierarchical branch of the Tucker lineage [28], [29].
TT factorization perfectly reconciles this conflict by inher-
iting the best of both worlds: it retains Tucker’s exceptional
data compression, controlled precision, and quasi-optimality,
yet completely neutralizes the parameter explosion by fac-
torizing the monolithic core into a chain of low-rank, third-
order core tensors. This structural mutation collapses the
storage and parameter complexity from an exponential
scale to a strictly linear scale, making it uniquely suited
for representing ultra-high-dimensional physical delay vari-
ations. Under the identical 64-bit 8-XOR configuration, CP-
based tensor modeling requires 364,700 trainable variables,
whereas TT-based TENAX uses only 1,042. Thus, TENAX
successfully unleashes the latent structural power of Tucker-
based optimization within a highly compact, sample-efficient
evaluation framework.

We evaluate TENAX across representative strong PUF archi-

SOTA penetration baselines. All experiments are conducted
on a server with 3.30 GHz CPUs, 125 GB RAM, and an

TENAX adopts the architecture shown in Fig. 3, config-

bias initialization, the Adam optimizer [32], binary cross-

dropout are applied to mitigate overfitting during backprop-

For simulation setups, stage delay parameters are inde-
pendently sampled from a Gaussian distribution N (0.1, 1)
following established protocols [3], [4], [18]. To emulate
real-world operational noise, an additive Gaussian noise term
N (0, 0.01) is applied to each stage delay.

To ensure rigorous comparison against prior pentesting
methods [3], [4], [6], [18]–[20], all algorithms are evaluated
over strictly identical datasets sampled from a pre-generated
ground-truth CRP pool per configuration. Controlled factors
span noise distributions, dataset splits, and evaluation met-
rics, guaranteeing that observed performance differentials
arise purely from algorithmic representation efficiency rather
than data variations.

To ensure fair comparison against established hardware
security evaluation approach [18], CRP datasets are parti-
tioned into an 80%-20% split between training and evalu-
ation sets by default. However, under extreme penetration
scenarios requiring massive CRP volumes, such as Linear
Modeling on a 128-bit 7-XOR APUF requiring 4 × 108
CRPs, a rigid 20% test ratio yields an oversized evaluation
set (> 108 CRPs), inducing prohibitive memory overhead.
To maintain computational tractability while preserving sta-
tistical integrity, we adaptively adopt a 99%–1% split in
these high-volume regimes. Because the resulting evaluation
set still encompasses over 4 × 106 CRPs, statistical confi-
dence is fully maintained without memory bottlenecks.

VI. Conclusion

We propose TENAX, a general paradigm for query-
constrained PUF security evaluation built around Tensor-
Train computation. TENAX resolves three core bottlenecks
pervasive within existing PUF assessment pipelines, which
are excessive parameter complexity, unfavorable efficiency-
accuracy trade-offs, and insufficient generalization across di-
verse strong PUF constructions. Its performance gains stem
from three coordinated design choices, i.e., compact Tensor-
Train factorization to bound parameter scale, native PCA
feature expansion to boost CRP utilization, and an end-to-
end pipeline natively compatible with XOR APUFs, iPUFs,
LSPUFs, and FPGA silicon implementations. By pushing
the boundaries of vulnerability assessment under extreme
query starvation, TENAX achieves consistent performance
gains across all tested PUF variants. Crucially, identifying
the critical query thresholds required for effective pentesting
helps define reliable security margins, providing a grounded
foundation for designing secure PUF authentication proto-
cols in real-world deployments.
